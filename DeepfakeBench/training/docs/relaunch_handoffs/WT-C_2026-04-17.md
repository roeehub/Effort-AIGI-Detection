# WT-C Augmentation / Nuisance Invariance Handoff

## Scope

WT-C re-investigated the live `quality_targeted_family` augmentation path,
confirmed which nuisance controls are actually active at runtime, and added one
narrow truthful sidecar family without editing the active Track A baselines.

## Runtime Truth

### What is live today on non-Teams families

Under `augmentation.version: quality_targeted_family` with
`strength: vcd_targeted`, the non-Teams family pipelines still do receive:

- `RandomGamma`
- `RandomBrightnessContrast`
- `ShiftScaleRotate`
- `ColorTemperatureShift`
- JPEG / blur / noise / downscale variation
- sharpen / real-noise / webcam-codec steps where configured

This means the repo does already have some lighting and crop nuisance coverage
outside the direct Teams passthrough branch.

### What was dead config intent

Active `phase2_round13` baselines request:

- `gamma_up_p`
- `gamma_up_range`

Those names are not consumed anywhere in the runtime path.

The real runtime key names are:

- `context_variation_gamma_up_p`
- `context_variation_gamma_up_range`

There was also a second drop layer: `combined_paired.py` derives valid preset
override keys from the **first** preset dict only. Before this WT-C patch, that
first preset did not expose the optional `context_variation_gamma_up_*`,
`context_variation_cct_*`, or related sidecar keys, so even correctly renamed
GammaUp keys would still have been filtered out before they reached the router.

### What stays weak on the exact Teams branch

`_build_teams_passthrough_pipeline()` is still intentionally minimal:

- `HorizontalFlip`
- light `RandomBrightnessContrast`

It does **not** add GammaUp, CCT, blur/downscale, codec simulation, or spatial
jitter to direct Teams rows. WT-C kept that branch unchanged in this patch to
avoid silently mutating the active deployment-relevant path.

## Code Changes

### Augmentation plumbing

`DeepfakeBench/training/data/augmentations/pipelines.py`

- added the optional lighting / sidecar key surface to the `light`,
  `moderate`, and `strong` preset dicts
- this makes the current first-preset allowlist admit the truthful runtime keys
  without changing baseline behavior
- active Track A YAMLs remain unchanged because they still use the old dead
  `gamma_up_*` names

### Sidecar family

Added two fresh sidecars under `phase2_round13`:

- `R13_WTC1_gammaup_plumbing_control_sidecar.yaml`
  - correct `context_variation_gamma_up_*` names
  - GammaUp kept at `0.0`
  - runtime-equivalent control for the plumbing surface
- `R13_WTC2_gammaup_truthful_sidecar.yaml`
  - correct `context_variation_gamma_up_*` names
  - GammaUp enabled at `0.15`
  - no other augmentation changes

### Tests

Updated:

- `DeepfakeBench/training/tests/test_lighting_transforms.py`
- `DeepfakeBench/training/tests/test_teams_adaptive_simulation.py`

Added coverage for:

- preset key-surface regression
- `vcd_targeted` default CCT-vs-GammaUp truth
- default Teams passthrough minimality
- proof that a GammaUp sidecar override changes non-Teams pipelines but does
  not silently mutate the Teams passthrough branch
