Verdict: PARTIAL — in_proj-SVD residuals are noise-dominated for L0–L4 (early layers, where camera-signature and image-quality shortcuts live), genuinely trained for L5–L11.

  • Median in_proj contribution L2 = 0.060 vs out_proj 1.36 (23× smaller)
  • Total non-zero residual params = 5.31M (1.77M in_proj + 3.54M other)
  • This refines the "B16 capacity ceiling" framing: it's ~2× self-imposed and concentrated in early-layer attention QKV, not 4× across all layers

Three non-exclusive interpretations

  1. Effort's orthogonal regularization spread weight across many singular directions. `lambda_reg=0.01` orthogonality pressure prevents the head from concentrating discriminative weight on a single axis.
  2. P8A FT'd toward the teams-domain axis (its training contract rewarded teams in-domain recall + reals-FPR), which is only weakly correlated with viso fake-ness. Anti-shortcut FT specifically pushed signal AWAY from pixel-quality and identity-cluster axes — but viso fake-ness lives partly on those same axes.
  3. 5-stage FT ossification. Each FT stage narrows the activation manifold. By P8A (4 prior stages + 1 current), the representation is highly fitted to teams-domain + camera-signature mitigation, with viso discriminability as collateral damage.

All three interpretations support: revisit "scratch from CLIP" or "very-light FT" as the next packet direction. P13 from-scratch was rejected on cross-domain regression but ran before the in_proj-SVD fix (Stream A), before the P22 aug curriculum, and without the eval-targeted aug distribution Stream C just identified.

Where do we go next? (post-Stream-A, B, C — all complete)

All three streams converge on a story. The 27% viso ceiling has at least three independent contributors:

  • Stream A: P8A's early-layer attention QKV residuals never trained (in_proj-SVD bug). The pixel-level processing where shortcuts live has half its capacity dead.
  • Stream B: The 5-stage FT chain diffused viso signal across more axes than CLIP carried. P8A loses 9–17pp under classifier stress.
  • Stream C: Eval viso is 5.3× softer and +51 brighter than training viso. The model never saw the eval distribution during training.

Three independent failure modes, three different fixes. Sequencing matters because the cheapest fix is also the most narrowly targeted, while the broadest fix is the most expensive.

Recommended sequence (ordered by evidence-per-dollar)

  1. Eval-targeted aug curriculum (P22-sister, ~$15-25). Highest evidence-per-dollar. Shift aug distribution toward eval-viso joint (laplacian ~50-150, luma ~135-185), single lever. Stream C provides direct mechanistic evidence. Risk: if Stream B's FT-diffusion is the binding constraint, no amount of aug will help (the discriminative direction is already diluted in the loaded P8A representation).
  2. Scratch from CLIP-B16 + aug curriculum + post-Apr-26 fixes (~$50). Strongest evidence for breaking the FT cycle. Stream B directly licenses this. Stream A's early-layer dead capacity goes away with fresh init. Stream C's aug evidence applies. The three things P13's scratch attempt was missing: (a) in_proj-SVD gradient fix (post 2026-04-26), (b) P22 aug curriculum, (c) eval-targeted aug distribution. Risk: cross-domain regression that killed P13 before. Mitigation: include the post-P22 sampling discipline + test contract scorecard at multiple training lengths.
  3. Rank-restoration FT (~$40, novel). Cheaper alternative to scratch. Stream B's interpretation (Effort orth-reg spread weight too thinly) suggests reversing it: concentrate signal back onto top-k singular axes via inverse-Effort regularization. Untested in this codebase. Worth a CPU pre-test (run the C-sweep probe on a lightly-FT'd rank-restoration ckpt) before GPU spend.
  4. Selective L0-L4 in_proj re-init (~$30-40). Tests Stream A directly. Re-init the 13 noise-dominated slots, FT 1-2k steps. Cheaper than full scratch, but doesn't address Stream B (FT diffusion) or Stream C (aug distribution). Useful as a 4th-priority test to decompose the contribution of each finding.
  5. L14 swap (~$60, user budget approved). Reserve for last. Removes the documented B16 capacity ceiling; closer to original Effort paper. But all three CPU diagnostics suggest B16 has live problems that are independent of architecture (FT diffusion + aug distribution + early-layer dead capacity). Run L14 only if (1)+(2) both fail.

Cost-bound recommendation: if the user has ~$40-65 of budget, spend it on (1) eval-targeted aug first. If recall lifts above 35-40%, the binding constraint was aug distribution and the win can be replicated cheaply. If recall stays at ~25%, the FT-diffusion (Stream B) is binding and the next move is (2) scratch with curriculum, NOT L14.

If the user has ~$80+ available: run (1) and (2) as a planned pair. Both share infrastructure (yaml + image build). Hold L14 ($60) for the case where both B16 options fail.

If the user wants the biggest swing right now: skip (1) and run L14 directly. Risk: a cheaper test (1) might have been sufficient, and the L14 one-shot is gone. Only justified if the user wants to definitively validate or rule out the architecture-capacity hypothesis.
