## Configuration

P12 was the direct response to P11's day-2 verdict β: **HEAVY's anchor_mean continuously improved through step 6000, but the trainer's AUC-ranked save policy froze on step 1000 (the WORST anchor moment).** The hypothesis: extend HEAVY's schedule to 8000 steps with periodic saves at 1000-step granularity to capture the recovery; the late-step checkpoint should land closer to HEAVY's true potential than step 1000.

User decision (09:30 CEST, `april-26-training-master-plan-v2.LOG.md:1234`): authorized parallel P12 launch to save 5h vs waiting for P11 inference verdict.

### Trainer patch (commit `c7dc828`, `april-26-training-master-plan-v2.LOG.md:1238-1241`)

`trainer/trainer.py` ~50 lines additive:

- Added `periodic_saves` config block that triggers `save_ckpt(prefix='periodic')` at fixed steps regardless of metric improvement.
- Inserted at end of value_composite save block, before `test_epoch` definition.
- Logs `periodic_saves/step_<N>/gcs_path` to W&B summary for traceability.
- Backwards-compatible: feature off by default (`enabled: false`).

The patch was authored with an `isinstance(dict)` defense pattern in mind — but the actual implementation **omitted the isinstance check**:

```python
periodic_cfg = self.config.get('periodic_saves') or {}
```

When `wandb.config.get('periodic_saves')` returns a wrapper that isn't a plain dict (or evaluates falsy on `or {}`), `periodic_cfg` becomes `{}` and `.get('enabled', False)` returns False — block silently skipped. **No log line, no error, no W&B summary entry.** The bug is silent specifically because the gate `if periodic_cfg.get('enabled', False)` evaluates to False without flagging.

This patch class is the **same bug class** as the wandb-flattening allowlist drift documented in [`wandb_flattening`](../threads/wandb_flattening.md): the trainer reads `self.config.get('periodic_saves')` which returns `None` after wandb flattens `periodic_saves.enabled` / `periodic_saves.step_list` into dotted keys; `or {}` evaluates the None to {}, and the gate falls through silently.

## Retrospective (as of 2026-04-29)

P12 is the packet whose **null result** is the load-bearing finding. The dud established three things:

1. **Pure-FT-extension is bounded** — the anchor recovery rate (~0.04 per 1000 steps) is empirically too slow to reach P8A's floor in achievable time. P11_HEAVY's "anchor recovers by step 3000" hypothesis is wrong.
2. **The `periodic_saves` patch class is a wandb-flattening recurrence** — the bug is structurally identical to the Slice-3 `value_composite` allowlist drift; the fix lives in `train_sweep.py`, not in defensive `isinstance(dict)` checks at the trainer layer. The Slice-6 commit `c366026` is the structural fix (allowlist + test guard).
3. **The substrate is bounded** (Option A subagent γ verdict 13:30 CEST) — inference-time stack alone cannot reach 90/5 because AUC(visomaster fake vs modern_v2 real) caps at ~0.65; calibration moves probabilities, not AUC. P12 + Option A together motivate Plan v4's substrate-redesign track.

**Three structural bugs interact with P12 attribution:**

1. **The wandb-flattening bug** (this packet's load-bearing failure mode) — `periodic_saves` is a new top-level nested-dict block; the trainer reads None; `or {}` falls through silently. Same root cause class as the Slice-3 `value_composite` allowlist drift; same root cause class as the P13 `anchor_aware` / `face_scale_jitter` failure 6 days later. Fix: `c366026` adds `periodic_saves` to the allowlist AND adds the `tests/test_train_sweep_reapply_allowlist.py` regression-test guard. See [`wandb_flattening`](../threads/wandb_flattening.md).
2. **The early-stopping AUC patience metric** — AUC saturates at step 1000; the early-stopping fires at step 6000 because no AUC improvement registers; meanwhile the anchor_mean is still recovering at +0.04 per 1000 steps. Fix: change patience metric to anchor or value_composite, or extend the patience parameter, or both. The Plan v4 P13_ANCHOR_AWARE recipe addresses this by introducing the anchor-aware loss term as a first-class objective.
3. **The contract policy bug** — at end of Slice 6, the contract policy fix is uncommitted; P12's would-have-been promotion-contract scorecard would have hit the τ-tail-collapse. P12 didn't reach the contract scorecard stage because the dud killed it earlier; the bug only would have bitten if P12 had produced a usable late-step checkpoint. The fix-attempt #2 (Slice 6, 2026-04-27 14:55) and fix-attempt #3 (Slice 7, 2026-04-29) are both documented in [`contract_policy_bug`](../threads/contract_policy_bug.md).
