## Configuration

P10 has two distinct halves that ran on different timelines in Slice 5:

### Half 1: P10 anti-shortcut packet authored 2026-04-26 morning (commit `2c9778b`)

- **Symmetric augmentation router** — augmentation pipelines apply the same codec / spatial / lighting transforms to both the real and fake passes, removing the asymmetry where fake-side codec aug fired heavier than real-side. The hypothesis: the camera/ISP shortcut is partly produced by codec asymmetry in training (fake clips get heavily codec-augmented, real clips do not, so the model learns "if it has codec artifacts it must be fake").
- **GRL slate** — an explicit gradient-reversal layer on the quality / domain head, designed to push the backbone toward features that the quality head cannot predict. Theoretically eliminates the camera/ISP shortcut at training time.
- This is the orthogonal intervention class to P8A/P9 (which soften an unfreeze recipe). P10 attacks the data and loss surfaces directly.

The GRL slate was not launched in Slice 5; the symmetric router yaml `R13_P10_SYM_on_P8A` was the only canonical P10 variant that ran (as part of Phase C.1; see Half 2).

## Retrospective (as of 2026-04-26)

**Packet is partially run.** P10's canonical training-side intervention — the symmetric router — ran as Phase C.1 + variants and produced the 5-corner readout above. The GRL slate did not run in Slice 5 (the broader P10 anti-shortcut packet was drafted but not launched as a clean P10-named packet). The Phase C readout is the closest thing to a P10 packet result, and it gives a mixed signal:

- **Positive**: C.3 codec_hedge looks like a real direction (+30% best_anchor/composite vs canonical) — codec aug intensity is a live lever.
- **Tied**: C.1 vs C-ablation (in_proj fix not exercised by recipe), C.4b vs C.4a (FT-depth crystallization not measurable at slate resolution).
- **Negative**: A.2 v3 readout shows P8A reference dominates P10_SYM-on-P8A step 2500 on both lockbox FPR + recall axes at τ=0.5; the §C.1 hypothesis is not supported at this checkpoint.

**Two structural conclusions for the next slice**:

1. **Codec is the live lever** — C.3 codec_hedge is the highest-priority follow-up; A.2-style validation against P8A reference + C.1 should rank it on lockbox FPR + per-method recall. If C.3 beats P8A on the crowning protocol, codec aug intensity becomes the canonical recipe knob.
2. **In_proj-SVD lever needs a different recipe** — the canonical P10_SYM-on-P8A recipe does not exercise the unlocked capacity. Future packets that want to claim in_proj-SVD as a lever need to (a) increase the SVD rank, (b) add a regularizer that uses the unlocked residual, or (c) fork from a less-crystallized base.

**Retroactive in_proj-SVD correction**: The P10 yaml `R13_P10_SYM_on_P8A.yaml` was authored before the in_proj fix (commit `2c9778b` predates `2feea58`); the C.1 run on image 1.3.216 was the first canonical P10 run on the post-fix code path. Earlier P10 yaml drafts (and the GRL slate yamls, never run) are silent-bug-era artifacts; they would need a refresh against the post-fix image before any P10-named launch.

**Preprocessing-parity note.** Phase C runs are **post-fix** (commit `855871e`).

**The packet's contribution to the program narrative**: P10 is the first time the team explicitly framed "softening P8A" (P9) and "anti-shortcut intervention" (P10) as orthogonal intervention classes, rather than two ways of fixing the same problem. P9 keeps P8A's recipe and dials it; P10 changes the loss + augmentation surface. The Phase C readout suggests the codec axis (which P9_05 also targets via `real_codec_uplift`) is the strongest single lever; the broader P10 GRL slate may or may not be needed depending on Slice 6's P9 readout.
