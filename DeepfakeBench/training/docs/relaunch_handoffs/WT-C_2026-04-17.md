# WT-C Augmentation / Nuisance Invariance Handoff

## Scope

WT-C re-investigated the live `quality_targeted_family` augmentation path,
confirmed which nuisance controls are actually active at runtime, and added one
narrow truthful sidecar family without editing the active Track A baselines.

## Runtime Truth

### What is live today on non-Teams families

Under `augmentation.version: quality_targeted_family` with
`strength: vcd_targeted`, the non-Teams family pipelines still do receive:

- `RandomGamma`
- `RandomBrightnessContrast`
- `ShiftScaleRotate`
- `ColorTemperatureShift`
- JPEG / blur / noise / downscale variation
- sharpen / real-noise / webcam-codec steps where configured

This means the repo does already have some lighting and crop nuisance coverage
outside the direct Teams passthrough branch.

### What was dead config intent

Active `phase2_round13` baselines request:

- `gamma_up_p`
- `gamma_up_range`

Those names are not consumed anywhere in the runtime path.

The real runtime key names are:

- `context_variation_gamma_up_p`
- `context_variation_gamma_up_range`

There was also a second drop layer: `combined_paired.py` derives valid preset
override keys from the **first** preset dict only. Before this WT-C patch, that
first preset did not expose the optional `context_variation_gamma_up_*`,
`context_variation_cct_*`, or related sidecar keys, so even correctly renamed
GammaUp keys would still have been filtered out before they reached the router.

### What stays weak on the exact Teams branch by default

`_build_teams_passthrough_pipeline()` is still intentionally minimal:

- `HorizontalFlip`
- light `RandomBrightnessContrast`

It does **not** add GammaUp, CCT, blur/downscale, codec simulation, or spatial
jitter to direct Teams rows unless a sidecar explicitly opts into the new
special-augmentation block. The default deployment-relevant path stays
unchanged.

## Code Changes

### Augmentation plumbing

`DeepfakeBench/training/data/augmentations/pipelines.py`

- added the optional lighting / sidecar key surface to the `light`,
  `moderate`, and `strong` preset dicts
- this makes the current first-preset allowlist admit the truthful runtime keys
  without changing baseline behavior
- active Track A YAMLs remain unchanged because they still use the old dead
  `gamma_up_*` names
- added a new opt-in Teams passthrough special-augmentation block with explicit
  YAML knobs and no behavior change unless
  `teams_passthrough_special_aug_enabled` is set to `true`

### Teams passthrough special-augmentation knobs

These knobs now exist and are safe by default:

- `teams_passthrough_flip_p`
- `teams_passthrough_brightness_contrast_p`
- `teams_passthrough_brightness_limit`
- `teams_passthrough_contrast_limit`
- `teams_passthrough_special_aug_enabled`
- `teams_passthrough_special_shift_p`
- `teams_passthrough_special_shift`
- `teams_passthrough_special_scale`
- `teams_passthrough_special_rotate`
- `teams_passthrough_special_cct_p`
- `teams_passthrough_special_cct_range`
- `teams_passthrough_special_shadow_p`
- `teams_passthrough_special_shadow_intensity`
- `teams_passthrough_special_shadow_softness`
- `teams_passthrough_special_gamma_up_p`
- `teams_passthrough_special_gamma_up_range`

Runtime contract:

- if `teams_passthrough_special_aug_enabled: false`, the Teams passthrough path
  stays on the current minimal two-step flow
- if `teams_passthrough_special_aug_enabled: true`, the sidecar can opt into
  light spatial jitter, colour-temperature shift, directional shadow, and/or
  GammaUp on direct Teams rows only

## Recommended Test Order

Test these changes in the following order so the plumbing is validated before
any training result is interpreted:

1. **Guardrail unit tests**

   Run the owned augmentation tests first:

   ```bash
   /tmp/wtc-py311/bin/python -m pytest \
     DeepfakeBench/training/tests/test_lighting_transforms.py \
     DeepfakeBench/training/tests/test_teams_adaptive_simulation.py
   ```

   This confirms the safety contract:

   - default Teams passthrough is still minimal
   - special Teams augmentation does nothing unless explicitly enabled
   - non-Teams GammaUp overrides stay isolated from the Teams branch

2. **Local config dry-runs**

   Dry-run each WT-C sidecar before spending remote compute:

   ```bash
   python3 DeepfakeBench/training/train_sweep.py --param-config \
     DeepfakeBench/training/experiments/phase2_round13/R13_WTC1_gammaup_plumbing_control_sidecar.yaml \
     --dry-run

   python3 DeepfakeBench/training/train_sweep.py --param-config \
     DeepfakeBench/training/experiments/phase2_round13/R13_WTC2_gammaup_truthful_sidecar.yaml \
     --dry-run

   python3 DeepfakeBench/training/train_sweep.py --param-config \
     DeepfakeBench/training/experiments/phase2_round13/R13_WTC3_teams_passthrough_special_shadow_sidecar.yaml \
     --dry-run
   ```

   This checks that the YAMLs parse cleanly through the live training entry
   point and that the sidecars remain launchable without touching the active
   Track A baselines.

3. **Run the neutral plumbing control first**

   Launch `R13_WTC1_gammaup_plumbing_control_sidecar.yaml` before any real
   augmentation treatment.

   Recommended purpose:

   - prove the corrected runtime key surface is neutral when GammaUp stays off
   - catch any unexpected training drift caused by plumbing alone

4. **Run one nuisance hypothesis at a time**

   Launch the current truthful sidecars in this order:

   - `R13_WTC2_gammaup_truthful_sidecar.yaml`
   - `R13_WTC3_teams_passthrough_special_shadow_sidecar.yaml`

   Keep these separate. Do not combine GammaUp, shadow, CCT, and spatial jitter
   in one first-pass run.

   Recommended interpretation order:

   - `WTC2` asks whether truthful non-Teams brightening improves nuisance
     robustness
   - `WTC3` asks whether a light direct-Teams shadow treatment helps on the
     deployment-relevant branch

5. **Measure before adding more knobs**

   After each run, hand the resulting checkpoints to WT-D / the existing
   scorecard flow before creating another sidecar. The next acceptable WT-C
   follow-ups are single-knob sidecars only:

   - Teams passthrough CCT
   - Teams passthrough GammaUp
   - Teams passthrough light ShiftScaleRotate

   Avoid multi-knob mixes until at least one single-effect sidecar shows a
   defensible slice win.

For remote execution, use the same Round 13 launcher pattern already documented
in `R13_PLAN.md`, swapping in the WT-C sidecar path:

```bash
./launch_experiment.sh -y phase2r13-experiments asia-southeast1 \
  experiments/phase2_round13/R13_WTC1_gammaup_plumbing_control_sidecar.yaml
```

Repeat that with `WTC2` and `WTC3` only after the earlier step in the sequence
is complete.
