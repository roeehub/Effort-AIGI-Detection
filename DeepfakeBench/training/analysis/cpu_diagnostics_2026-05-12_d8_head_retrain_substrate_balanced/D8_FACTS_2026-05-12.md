# D8 — Head retrain with substrate-balanced real pool — FACTS (2026-05-12)

> **Status: factual-only.** Forbidden words: succeeds, fails, wins, loses, promotes, deployment-grade, unfortunately, remarkably, shortcut-aligned, lucky, confirmed, refuted, breakthrough, ceiling-breaking. Numbers + tables + cross-references only. Interpretation belongs in a sibling OPINIONS doc.
>
> **What was measured**: P8A_step5000 frozen-encoder L11 features were used to fit four linear-logistic heads on the dev pool. Three of the four heads used per-sample importance weights on the dev-real subset, computed from three different density-ratio estimators in CLIP-frozen feature space, targeting the lockbox-real distribution. Each head was then evaluated under: (a) DEV→LOCKBOX AUC transfer, (b) LOCKBOX→DEV AUC transfer (unweighted reference only), (c) 5-fold in-sample CV AUC, (d) lockbox FPR at the dev-calibrated 5% FPR threshold τ.
>
> **Inputs unchanged from D3 / scaled-layer-validation cache**: P8A frozen encoder, L11 CLS, 4000 dev frames (2000 real + 2000 fake) + 839 lockbox frames (414 real + 425 fake), sampled with `numpy.default_rng(seed=42)` from `analysis/lockbox_tagging/full_tags_2026-04-27.parquet`. CLIP-frozen features extracted on MPS with OpenCLIP ViT-B-16 DataComp.XL weights to depth L11 CLS. No GPU spend.

## 1. Method

### 1.1 Inputs

| Resource | Path | Shape / count |
|---|---|---|
| P8A L11 cache | `analysis/_features_cache_2026-04-30/layer_validation__P8A__4000_839__layers_3_6_11.npz` | dev 4000×768, lockbox 839×768 |
| CLIP-frozen L11 cache (created here) | `outputs/clip_frozen_l11__n4839.npz` | 4839×768 |
| Eval manifest | `analysis/lockbox_tagging/full_tags_2026-04-27.parquet` | 7334 rows total |

Dev sampling reproduced from `scaled_layer3_validation.py`: stratified 2000 real + 2000 fake from the 6495 dev rows under seed=42.

### 1.2 CLIP-frozen extraction

OpenCLIP ViT-B-16 (`weights/CLIP-ViT-B-16-DataComp.XL-s13B-b90K/open_clip_pytorch_model.bin`), forward hook on `visual.transformer.resblocks[11]` capturing the CLS token (index 0). Preprocessing: 224×224 resize (cv2 INTER_LINEAR), RGB conversion, CLIP mean/std normalization. Batched on Apple MPS (32 per batch); 4839 frames extracted in ~104 s of wall time. All 4839 returned non-null features.

### 1.3 Three density-ratio estimators

For each dev-real frame x_i, an importance weight w_i ≈ p_eval(x_i) / p_train(x_i). Dev-fake frames are assigned w = 1.0 in every variant.

**Estimator A — primary (per brief)**: PCA(n_components=32) fit on combined dev+lockbox CLIP-frozen features (shared basis). Gaussian KernelDensity per side (sklearn), bandwidth per Silverman's rule h = σ_med · n^(-1/(d+4)) on each side. Weight w = exp(log p_eval − log p_train), clipped to [0.01, 100].

**Estimator B — robustness, low-dim KDE**: PCA(n_components=8); bandwidth = 2.0 × Silverman; otherwise identical to A.

**Estimator C — robustness, classifier (KLIEP)**: L2-normalize CLIP-frozen features, then fit `LogisticRegression(C=1.0, class_weight='balanced')` discriminating dev-reals (y=0) vs lockbox-reals (y=1). For dev-real x_i, w_i = p(y=1|x_i) / (1 − p(y=1|x_i)), rescaled so mean(w) over dev reals = 1. Clipped to [0.01, 100].

### 1.4 Head fits

`LogisticRegression(C=1.0, max_iter=2000, n_jobs=1, solver='lbfgs')` on `(dev_p8a, dev_labels)`. Weighted variants pass `sample_weight = w` where w[real] is the estimator output and w[fake] = 1.0. The same LR config is used to fit the LOCKBOX→DEV reference head (n_train=839 lockbox).

### 1.5 Evaluation

- Cross-substrate AUC via `roc_auc_score(test_labels, predict_proba[:,1])`.
- Bootstrap CI: 100 resamples of test-set indices with replacement, seed 42, 2.5/97.5 percentile.
- 5-fold stratified CV AUC: `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)`. Weighted variants pass weights into the per-fold fit.
- τ calibration: smallest τ such that fraction(dev_real_score ≥ τ) ≤ 0.05.
- Lockbox FPR / recall reported at that τ.

Constraints: `n_jobs=1` per `feedback_sklearn_njobs.md`; deterministic seed 42; CPU-only for sklearn (MPS used only for CLIP-frozen feature extraction).

Scripts: `run_d8.py` (single-file pipeline). Total wall time: 159 s (cached CLIP) / 263 s (cold CLIP extraction).

## 6. Caveats

1. **Primary estimator (PCA(32) Silverman KDE) clip-floor collapse**: 2000 / 2000 unclipped weights are below 0.01 (max 1.46e-09), so after clipping every dev real receives weight 0.01 (uniform). The trained head still differs from the unweighted head because of the constant-multiplier effect of all-low real weights vs unit fake weights, but the spatial/per-frame substrate-balance signal is not retained. This is a known regime issue for KDE-density-ratio estimation in d ≥ ~20 with Silverman bandwidths and source/target imbalance (n_train=2000, n_eval=414). Reported as primary per the brief; estimators B and C added as robustness probes.
2. **Estimator B (PCA(8) Silverman ×2 KDE) effective sample size = 39.8** (out of 2000 dev reals): top-1% of dev reals carries 44.8% of the post-clip mass; top-10% carries 86.7%. The dev pool is effectively reduced to ~40 reals during head fit. 1031 / 2000 reals are still at the lower-clip floor.
3. **Estimator C (classifier KLIEP) effective sample size = 268.8** (out of 2000 dev reals); no weights at the clip floor. The discriminator LR achieves 0.99 class-balanced accuracy at distinguishing dev-real from lockbox-real, indicating the two real pools are linearly separable in CLIP-frozen feature space.
4. **CLIP-frozen extraction n=4839 vs D2 n=800**: the CLIP-frozen cache at `analysis/cpu_diagnostics_2026-05-12_d2_encoder_separation` covers only the 800-frame triptych; D8 re-extracted CLIP-frozen for the full 4839-frame dev+lockbox split via the same hook protocol. Spot checks were not performed to verify exact numeric agreement on the overlapping 459+87 frames; the script applies the same hook and preprocessing as D2.
5. **No training-pool features extracted**: D8's "training pool" maps to the dev real pool (n=2000), not the actual training data buckets used for the original P8A training run. The "eval real" target is the lockbox real pool (n=414). This matches the D3 head-training and D4 calibration setup.
6. **τ-calibration sample**: dev-real n=2000 → 5% FPR target = top 100 scores. The exact achieved dev FPR for each head is 0.0500 by construction (k = ⌈0.95 · 2000⌉ = 1900, τ = sorted_real_scores[1900]).
7. **LOCKBOX→DEV is unweighted only**: the brief's substrate-balance scheme requires a "source" pool to reweight toward a "target" distribution. When training-source = lockbox, the natural target distribution is the dev real pool; this experiment was not run in D8 (the brief framed it as the inverse direction).
8. **Encoder unchanged**: every head is fit on the same frozen P8A L11 CLS features; the encoder weights are not touched. Comparing the four heads isolates the head-induced contribution to transfer.
9. **No identity-blocking**: dev and lockbox pools have known identity overlap (memory `project_lockbox_identity_looseness`); the LR fits and the importance-weight estimators do not deduplicate by identity, so weight assignments can be driven partly by identity-membership signal in the CLIP-frozen space, not purely by capture/IQ axes.
10. **Single-checkpoint scope**: D8 measures P8A_step5000 only. The brief did not request multi-ckpt extension. T5C/E2B/T3_S1 features at the 800-frame level are in `analysis/iq_perlayer_probe_2026-05-08/_cache/` if needed.
11. **D3's "DEV→LOCKBOX 0.594" baseline used 800 frames**; D8's 0.5865 baseline uses 4839 frames. The 0.0071-point shift is well within bootstrap noise on either side and reflects sample-size change rather than methodology change.

## 9. Open questions (factual, not interpretive)

1. The D8 unweighted offline-LR head has 72.22% lockbox FPR at dev-5% τ; the in-loop P8A head (same encoder weights) has ~0.92% lockbox FPR per D4. The head-construction differences (joint trainable encoder-final-block + ArcFace-style loss vs offline L11-features LR with BCE) have not been decomposed.
2. Estimator A's all-clip-floor outcome is a property of PCA(32) + Silverman bandwidth in this sample regime; the brief did not pre-specify which bandwidth or whether to allow lower-dim PCA. Whether a different sklearn KDE bandwidth or estimator (e.g. uLSIF, RuLSIF) reaches the +0.08 to +0.09 AUC lift seen for estimators B and C with cleaner weight distributions is not measured.
3. The 99.09% LR-discriminator training accuracy on (dev-real vs lockbox-real) in CLIP-frozen feature space (estimator C) indicates the two pools are nearly linearly separable. Identity-leak vs capture/IQ-axis contribution to this separability is not decomposed in D8.
4. The estimator-C head matches the unweighted head on dev_fake_recall and lockbox_fake_recall (both 1.0 dev, both 0.9906 lockbox) but reduces lockbox_FPR by 4.1 percentage points. Estimators A and B sacrifice lockbox_fake_recall by 4.4-4.7 percentage points to achieve comparable FPR reductions (3.9 to 5.8 pp).
